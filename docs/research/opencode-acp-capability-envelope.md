# OpenCode ACP Capability Envelope

**Status:** Research conclusion for [Establish OpenCode ACP's capability envelope on all target platforms](https://github.com/secantdev/secant/issues/176)

**As of:** 2026-09-20

**OpenCode examined:** stable [`v1.18.31`](https://github.com/anomalyco/opencode/releases/tag/v1.18.31), source commit [`014614d35b397775e5d397a490fc72368c894ec2`](https://github.com/anomalyco/opencode/tree/014614d35b397775e5d397a490fc72368c894ec2)

**Protocol implementation examined:** official TypeScript ACP SDK [`v0.21.0`](https://github.com/agentclientprotocol/typescript-sdk/tree/74372b59f8f56eb30e72f2538df2671a0adb376f), the version pinned by OpenCode ([manifest](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/package.json#L50-L62))

## Evidence Labels

- **Documented:** stated by official OpenCode, ACP, or release documentation.
- **Source-observed:** directly visible in first-party source at the pinned commits above.
- **Locally observed:** reproduced with the pinned release binary on the named research host; never a cross-platform claim.
- **Inferred:** the narrow consequence supported by documented, source, or runtime evidence but not itself promised upstream.
- **Unknown:** current primary evidence and permitted runtime checks do not establish the behavior.

## Answer

OpenCode `v1.18.31` exposes a substantial ACP v1 Harness surface over newline-delimited JSON-RPC 2.0 on stdin/stdout. It has an authoritative prompt-response boundary, stable native Session identity before the first prompt, streamed assistant/thought/tool/usage events, structured permissions, prompt cancellation, dynamic model/effort/mode configuration, and three distinct persisted-conversation operations: replaying load, no-replay resume, and replaying fork. It also supports list and close. OpenCode documents the subprocess shape ([pinned ACP documentation](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/web/src/content/docs/acp.mdx#L16-L21)); the implementation and initialization response establish the wider envelope ([launch](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/cli/cmd/acp.ts#L9-L72), [capabilities](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L94-L139)). **Documented, source-observed, and locally observed on macOS arm64.**

The fit is not parity with the Secant Harness Interface. OpenCode exposes no native same-Turn Steer and no structured clarification/elicitation path in its Agent implementation; an ordinary assistant question is only streamed text ending at the prompt response. `session/cancel` is a notification whose acknowledgement is only the later prompt result, and OpenCode deliberately swallows backing-session abort failure. Closing a Session removes only process-local ACP attachment state and best-effort aborts active work; it preserves the stored conversation. Process shutdown is stdin EOF, not a shutdown RPC. These boundaries are visible in the complete Agent method surface and lifecycle code ([Agent methods](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/agent.ts#L32-L86), [cancel/close](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L336-L360)). **Source-observed.**

OpenCode publishes binaries for Windows, macOS, and Linux and runs the repository unit suite, including ACP tests, on Linux and Windows. Its checked-in ACP subprocess tests cover real-process initialization, auth negotiation, EOF, lifecycle, model/effort configuration, prompt content, and skills against a deterministic local model server. Upstream does not run that matrix on macOS, and no primary evidence proves installed release-binary ACP parity on all three systems ([build targets](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/script/build.ts#L53-L114), [test matrix](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/.github/workflows/test.yml#L23-L66)). **Source-observed and unknown.** Secant must qualify each target OS; this report directly qualifies only the pinned macOS arm64 binary.

## Launch, Transport, Initialization, And Versioning

- The public command is `opencode acp`. It starts an internal server on an OS-assigned loopback port, constructs a private generated SDK client, bridges stdin/stdout through the official ACP SDK's NDJSON stream, and waits for stdin EOF ([command implementation](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/cli/cmd/acp.ts#L19-L72)). **Source-observed.** The loopback server is OpenCode-internal transport; Secant must speak only ACP stdio and must not depend on, discover, or expose its port.
- The SDK serializes one `JSON.stringify` value plus newline, incrementally decodes stdin, and accepts a final unterminated JSON value at EOF ([SDK stream](https://github.com/agentclientprotocol/typescript-sdk/blob/74372b59f8f56eb30e72f2538df2671a0adb376f/src/stream.ts#L26-L98)). **Source-observed.** Secant's side should retain its strict owned NDJSON framing and raw recording rather than inherit this permissive reader.
- The pinned SDK prints an entire malformed input line to stderr and drops it; its connection error paths can also log full request/notification objects ([malformed lines](https://github.com/agentclientprotocol/typescript-sdk/blob/74372b59f8f56eb30e72f2538df2671a0adb376f/src/stream.ts#L51-L74), [request logging](https://github.com/agentclientprotocol/typescript-sdk/blob/74372b59f8f56eb30e72f2538df2671a0adb376f/src/acp.ts#L1416-L1446)). **Source-observed.** This is incompatible with treating ordinary stderr as safely retainable diagnostics. Use the official SDK for ACP vocabulary/correlation behind a Secant-owned strict Stream, redact/drop untrusted stderr payloads, and treat malformed/truncated/extra stdout as transport corruption.
- Initialization always returns protocol version `1`, even though the service does not compare the client's requested major. It advertises `loadSession`, close/fork/list/resume, HTTP/SSE MCP, images, and embedded context; auth is `opencode-login` with optional terminal-auth command metadata ([initialize](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L94-L146)). **Source-observed.** Secant must request major `1`, require returned major `1`, and use advertised capabilities plus its pinned conformance probe rather than treating major `1` as a complete feature contract.
- OpenCode pins SDK `0.21.0`; that release includes stable close/resume but still marks fork and legacy model selection unstable in its Agent interface ([resume/close/fork contracts](https://github.com/agentclientprotocol/typescript-sdk/blob/74372b59f8f56eb30e72f2538df2671a0adb376f/src/acp.ts#L1961-L2014), [legacy model method](https://github.com/agentclientprotocol/typescript-sdk/blob/74372b59f8f56eb30e72f2538df2671a0adb376f/src/acp.ts#L2032-L2053)). **Source-observed.** Prefer stable session config options; classify fork as version-pinned even though OpenCode advertises it.

## Sessions, Admission, Recovery, And Replay

- `session/new` loads a directory-scoped snapshot of providers, visible primary agents, commands, skills, configuration, and MCP; creates a stored OpenCode Session; returns its native ID and current config options; and asynchronously announces commands ([new Session](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L148-L209), [snapshot](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L743-L797)). **Source-observed.** The request `cwd` is workspace authority. The returned ID is available before any prompt, so a Secant Adapter can durably record the recovery coordinate and fail `not-started` before submitting content.
- `session/load` fetches the exact stored Session and all messages for the supplied ID and directory, restores model/effort/mode, registers MCP, sends commands, then awaits sequential replay before returning ([load](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L211-L247), [sequential replay](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L692-L699)). **Source-observed.** This is truthful `load-with-replay`; replay must be historical, deduplicated from retained Secant facts, and separated from live progress by an Adapter-owned barrier before the next Turn.
- `session/resume` restores the same native ID and configuration from durable Session/message state but intentionally emits no historical message chunks ([resume](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L295-L334)). **Source-observed.** This qualifies as native reattach when the exact ID is acknowledged and a status probe succeeds; failure must make the Secant Session `unusable`, never open a fresh Session silently.
- `session/fork` creates a distinct stored Session ID, restores configuration, and replays the forked history before returning ([fork](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L362-L407)). **Source-observed.** Fork is not recovery of the original Session and must not substitute for resume.
- `session/list` merges live process-local entries with durable root Sessions, newest first, and paginates at 100 using an updated-time cursor ([list](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L249-L293)). **Source-observed.** It is useful as a read-only recovery probe, not Run truth.
- Closing removes process-local ACP state and best-effort aborts work; it does not delete the stored Session. There is no delete method in OpenCode's ACP Agent surface even though newer ACP artifacts may define one ([close implementation](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L336-L355), [Agent surface](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/agent.ts#L32-L86)). **Source-observed.** Secant cleanup must not claim deletion or retention control.

## Model, Effort, Mode, And Commands

- New, loaded, resumed, and forked Sessions return stable `configOptions`. `model` selects an enabled `provider/model`; `effort` appears for a model with variants; `mode` selects a visible non-subagent agent. Changes update the in-memory ACP Session and affect later prompts ([config handlers](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L409-L495), [directory filtering](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L743-L795)). **Source-observed.** Requested and effective values must remain distinct: record the returned current option and later assistant metadata where available; never echo the request as proof.
- OpenCode also implements older `session/set_mode` and unstable `session/set_model`, but stable `session/set_config_option` covers all three controls and returns the refreshed option set ([Agent dispatch](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/agent.ts#L68-L78), [config response](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L409-L495)). **Source-observed.** A Secant Adapter should not depend on the unstable legacy model method.
- Commands and skills are exposed as `available_commands_update`; known slash commands call OpenCode's command endpoint and `/compact` calls summarize ([prompt command path](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L509-L589), [command update](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L1007-L1030)). **Source-observed.** Native skill discovery is useful capability evidence but does not replace Secant v1's canonical plain-path skill delivery.

## Prompting, Streaming, Tool Activity, And Turn Boundary

- `session/prompt` converts ACP content, selects the stored model/variant/mode, invokes the stored OpenCode Session, then waits for the global event subscription to observe that Session becoming idle. Only after queued updates have been awaited does it emit usage and return the prompt response ([prompt](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L509-L544), [idle barrier](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/event.ts#L74-L105)). **Source-observed.** The matching JSON-RPC response is the authoritative Turn boundary; `session.status: idle`, tool completion, process exit, or assistant prose is not.
- Live assistant text becomes `agent_message_chunk` keyed by OpenCode message ID; reasoning becomes `agent_thought_chunk` keyed by part ID. Updates for unknown Sessions and live user parts are ignored ([delta routing](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/event.ts#L191-L259)). **Source-observed.** Accumulate assistant chunks for the active prompt, exclude thought/tool/replay content from final assistant text, and synthesize one final assistant-content fact at the prompt response.
- Tool parts emit one `tool_call`, running updates, and terminal completed/error updates; shell snapshots are deduplicated while status-only progress remains visible ([tool routing](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/event.ts#L295-L399)). **Source-observed.** Normalize tools as observational activity, never as Turn completion or Step success.
- A successful prompt returns `end_turn`; aborted work returns `cancelled`; output limit returns `max_tokens`; content filtering returns `refusal`; provider auth becomes an auth-required JSON-RPC error; other prompt failures become typed internal errors ([prompt result mapping](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L839-L892)). **Source-observed.** `end_turn` means only mechanical Harness completion. Secant markers/validation above the Seam remain authoritative for the Step.
- OpenCode can send `usage_update` with used/context size and cumulative USD cost, and the final prompt result can carry input/output/thought/cache token counts ([usage update call](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L639-L681), [result mapping](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L839-L888)). **Source-observed.** Preserve observed usage/cost as optional facts; do not derive completeness from them.

## Permissions, Questions, Cancellation, And Interruption

- Tool permission is a client request with exactly three OpenCode options: allow once, allow always, or reject. Missing permission support, client failure, cancellation, or any unexpected selection becomes reject; permission requests are serialized per Session but different Sessions remain independent ([permission bridge](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/permission.ts#L20-L97)). **Source-observed.** Expose one Turn-scoped Secant Harness Request keyed to the native request, preserve the exact offered decisions, expire it at terminal, and resolve cancellation as reject/cancel rather than approval.
- Edit permissions may include proposed diff content and file locations, and an accepting client with filesystem-write capability can be asked to write the proposed result ([edit permission mapping](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/permission.ts#L99-L217)). **Source-observed.** Secant need not advertise client filesystem writes; workspace mutation can remain OpenCode-owned. Do not expose raw permission metadata beyond the normalized request/tool activity contract.
- OpenCode's Agent implements no ACP elicitation method and the service never calls the SDK's elicitation client operations ([complete Agent surface](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/agent.ts#L32-L86)). **Source-observed absence.** Structured clarification is unavailable. An assistant question at `end_turn` is ordinary content answered by a later Turn, not a Harness Request.
- No same-Turn input/steer method appears in the ACP Agent surface. **Source-observed absence** from the same complete surface. Secant must report Steer unavailable and must never emulate it by starting an overlapping or second prompt.
- `session/cancel` looks up the exact attached Session and invokes backing `session.abort`. The notification has no immediate response, abort failure is logged and swallowed, and only a later prompt response with `stopReason: cancelled` confirms interruption ([cancel](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L336-L360), [cancelled result](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L852-L863)). **Source-observed.** An accepted control receipt means notification written, not work stopped; reject further inputs, drain updates, and settle `interrupted` only on the correlated cancelled result. EOF/exit or abort-without-result is `lost`, not confirmed interruption.

## Failures, Authentication, And Shutdown

- OpenCode maps missing Session, invalid config/model/effort/mode/auth method to JSON-RPC `-32602`, unsupported operations to `-32601`, provider authentication to `-32000`, and service failures to `-32603` with bounded service/error-name detail ([error mapping](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/error.ts#L63-L96), [SDK codes](https://github.com/agentclientprotocol/typescript-sdk/blob/74372b59f8f56eb30e72f2538df2671a0adb376f/src/acp.ts#L1611-L1685)). **Source-observed.** Preserve numeric code, phase, request method/id, safe detail, possible effects, and original cause in typed Harness failures.
- OpenCode advertises one login method. When the client advertises terminal-auth it supplies `opencode auth login`; `authenticate` only validates that method and returns `{}`, while actual prompts/session work use provider credentials already owned by OpenCode ([auth implementation](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L94-L146)). **Source-observed.** Secant must never transport or scrape credentials; surface separate-login remediation and retry only after the user authenticates in OpenCode.
- Closing stdin closes the ACP input and makes the command return; there is no shutdown method in the Agent surface ([EOF lifecycle](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/cli/cmd/acp.ts#L45-L72), [Agent surface](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/agent.ts#L32-L86)). **Source-observed.** `close` should reject new work, cancel active prompts when possible, close stdin, wait a bounded grace period, then terminate/reap the process tree. Killing after a settled prompt is cleanup; losing a live prompt remains `lost`; cleanup failure cannot rewrite settled truth.

## Target Platforms

- The build produces arm64/x64 Linux (glibc and musl variants), arm64/x64 macOS, and arm64/x64 Windows binaries; release packaging uploads archives for those targets ([build matrix](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/script/build.ts#L53-L114), [packaging](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/script/build.ts#L235-L244)). **Source-observed.** Binary availability is not ACP behavioral parity.
- The upstream unit workflow runs on Ubuntu 24.04 and Windows 2025, so ACP unit and subprocess tests are intended to execute on both. There is no macOS unit job in this pinned workflow ([test matrix](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/.github/workflows/test.yml#L23-L66)). **Source-observed.** This is useful Windows/Linux evidence but not installed release-binary qualification, and it leaves macOS upstream CI unproven.
- **Windows:** release/build evidence and source tests exist, but no pinned installed-binary ACP run was available in this research environment. Process-tree termination, stdin EOF, paths/resources, loopback bind, permissions, cancellation, recovery, and stdout purity are **unknown** until Secant runs them on Windows.
- **Linux:** release/build evidence and source tests exist, but no pinned installed-binary ACP run was available in this research environment. The same behaviors are **unknown** until Secant runs them on Linux.
- **macOS:** the pinned official arm64 archive was directly exercised as described below. Intel macOS and other supported macOS versions remain **unknown**.

### Required three-OS qualification gate

Before a Secant profile claims OpenCode support on an OS, the pinned release binary must pass:

1. Asset identity/version, `opencode acp --help`, launch, loopback bind, and protocol-only stdout.
2. ACP v1 initialization, exact advertised capability capture, incompatible-major refusal, and terminal-auth metadata.
3. Isolated OpenCode state/config plus deterministic provider; new Session and recovery coordinate recorded before prompt bytes.
4. Streamed assistant/thought/tool/usage normalization and prompt-response terminal ordering, including slow consumer/backpressure.
5. Permission allow-once, allow-always, reject, client-cancel, and outstanding-request expiry at terminal.
6. Active prompt cancellation, confirmed `cancelled`, continued reuse, cancel/terminal races, and connection loss after possible effects.
7. Process restart with exact `session/resume`, exact `session/load` replay/history-live barrier, missing ID, and directory mismatch.
8. Model/effort/mode change with effective option evidence; invalid option typed failures.
9. Session close preserving durable history; stdin EOF graceful exit; bounded forced process-tree cleanup.
10. Malformed/truncated/duplicate/mismatched JSON-RPC and unexpected EOF/exit without logging payloads or hanging pending calls.

## Deterministic Testing Surface

- Upstream has isolated real-subprocess ACP tests. The harness fixes home/XDG/config/auth, disables plugins/autoupdate/models fetch, runs a local deterministic model server, frames ACP over real stdin/stdout, drains stderr, and closes stdin with a bounded termination fallback ([subprocess harness](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/test/lib/cli-process.ts#L1-L80), [ACP process handle](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/test/lib/cli-process.ts#L133-L183), [shutdown/framing](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/test/lib/cli-process.ts#L366-L466)). **Source-observed.** This is a strong provider-contract model Secant can reproduce without external credentials.

## Local macOS Runtime Observation

On 2026-09-20 the research host was macOS `26.6.2` arm64. The official `opencode-darwin-arm64.zip` for `v1.18.31` was downloaded; its SHA-256 was `caf7f31fa1aec2353ea859d4ef9ab824c6273d941b016e88d51193fa3028d34e`, matching the immutable release asset metadata. The binary reported `1.18.31`; `acp --help` exposed `--cwd`, network flags, log flags, and `--pure`. **Locally observed.**

The binary ran with isolated XDG/config/data/state paths and `--pure`; outside the filesystem/network sandbox it bound its private loopback server and spoke only JSON-RPC on stdout. With stdin closed it exited code `0` and emitted no stderr. **Locally observed.** The sandboxed first attempt failed at the private bind with `ServeError`, confirming that launch requires local socket authority even though ACP itself stays on stdio.

The real protocol probe observed:

- `initialize` returned major `1`, OpenCode `1.18.31`, the documented capability set, and terminal-auth metadata; `authenticate(opencode-login)` returned `{}`.
- `session/list` worked; `session/new` returned a durable `ses_…` ID plus current model and mode options before content submission.
- A free-model prompt streamed one keyed `agent_message_chunk` containing `ACP_OK`, then `usage_update` with context/cost, then a matching response with `stopReason: end_turn`, token usage, and the submitted `messageId` as `userMessageId`.
- After close, `session/load` emitted stored `user_message_chunk` and `agent_message_chunk` before its response. After another close, `session/resume` returned the same Session configuration without replayed message chunks. Repeated close succeeded.
- All output framing was one JSON object per line; stderr remained empty.

These observations establish one macOS arm64 happy path only. They did not exercise a paid/authenticated provider, tool activity, permissions, thought streaming, model/effort/mode mutation, fork, active cancellation, forced termination, corruption, crash recovery, Intel hardware, Windows, or Linux. **Unknown outside the observed path.**

## Truthful Secant Harness Adapter Constraints

1. **Own the process and strict transport.** Spawn the resolved `opencode acp` child without a PTY; reserve stdout for strict NDJSON; capture bounded/redacted stderr; keep the SDK vocabulary/correlation behind Secant's own Stream, deadlines, failure translation, and cleanup.
2. **Qualify exact evidence.** Bind the profile to executable identity, OpenCode version, platform, configuration posture, SDK/Adapter revision, and the passing conformance probe. Accept only ACP major `1` plus the exact capabilities exercised.
3. **Admit before content.** Open a native Session lazily, durably record its returned ID, and only then submit a prompt. Recording failure before prompt bytes is `not-started`.
4. **Use native recovery honestly.** Prefer exact `session/resume` for native reattach; expose `session/load` separately as load-with-replay; never substitute fork/new. Missing/rejected exact IDs make the Session unusable.
5. **Install a replay barrier.** Treat all load/fork updates before the response as historical, reconcile duplicates, publish a barrier, then admit live progress. Persisted Secant history remains canonical.
6. **Serialize Turns per prepared Harness.** One active Turn at a time; do not use another prompt as Steer. Report native Steer unavailable.
7. **Own submitted-message origin.** Emit the outgoing managed/human prompt boundary from the Adapter; do not wait for a live user echo or compare bodies.
8. **Use prompt response as terminal authority.** Drain/coalesce preview events, expire requests, close the event producer, then settle the result. Accumulate live assistant chunks into final content; exclude thought, tools, replay, usage, commands, and stderr.
9. **Keep Step authority above the Seam.** `end_turn` is mechanical completion only. Marker and output validation remain above the Harness Adapter.
10. **Keep tools observational.** Normalize pending/running/completed/error activity without making a tool or `idle` event a Turn boundary.
11. **Bridge exact permissions.** Preserve native request identity and the three decisions. Client cancellation/failure rejects; late replies lose to terminal expiry. Never auto-approve based on another Harness's policy.
12. **Report clarification unavailable.** Ordinary assistant questions end a Turn and receive a later Turn; do not fabricate a structured Harness Request.
13. **Treat cancellation as two-phase.** Writing `session/cancel` is only accepted control. Confirm `interrupted` from the correlated `cancelled` prompt result; connection/process loss while effects may have begun is `lost`.
14. **Prefer stable config options.** Discover and set model/effort/mode through `session/set_config_option`, then retain returned current values. Do not rely on unstable legacy model/fork APIs unless separately pinned and qualified.
15. **Keep authentication OpenCode-owned.** Carry no credentials; expose `opencode auth login`; map provider auth errors to typed separate-login remediation. Initialization/authenticate success does not prove a provider prompt is authenticated.
16. **Separate Session detach from process cleanup.** `session/close` preserves stored history. Adapter `close` must also close stdin, wait, and reap the whole process tree; cleanup outcome cannot rewrite settled Turn truth.
17. **Preserve typed failures.** Distinguish discovery, launch/bind, initialize/version, native Session, admission/recording, prompt, auth, JSON-RPC, transport/EOF, cancellation uncertainty, recovery, and cleanup. Retain useful safe diagnostics and cause; never retain raw payload-bearing SDK stderr by default.
18. **Gate each OS independently.** Windows, macOS, and Linux profile claims remain unavailable until their pinned release binary passes the required gate. This report supplies only a macOS arm64 happy-path observation.

## Newly Sharp Follow-up Decision Questions

1. **Recovery preference:** Should Secant use native no-replay `session/resume` first and reserve `session/load` for reconciliation, or deliberately prefer load-with-replay to independently verify native history? Both exist and imply different evidence/barrier costs.
2. **State scope:** Should an OpenCode Adapter inherit the user's normal OpenCode config/data/auth, or run under isolated XDG/config state and require explicit authentication/materialization? This determines discovery, privacy, recovery visibility, and determinism.
3. **Process topology:** Is OpenCode's required private loopback server acceptable inside Secant's supported sandbox/deployment environments, and which bind failure should Preflight classify?
4. **Permission ownership:** Should Secant advertise/client-host ACP filesystem-write capability for proposed edits, or leave all workspace writes inside OpenCode's tool execution path? The latter is narrower and sufficient for the Harness Seam.
5. **Fork scope:** Does any v1 Step need native Session fork? It is useful but unstable ACP and is not needed for ordinary Run recovery.
6. **Protocol dependency shape:** Which exact official-SDK surface should Secant retain behind its strict custom Stream, and how will it suppress the pinned SDK's payload-bearing console logging without forking protocol vocabulary?
7. **Qualification ownership:** Will Secant vendor/adapt OpenCode's local deterministic provider fixture, or record a smaller protocol fixture plus a separate opt-in real-binary provider server? The gate must test the release binary, not merely OpenCode source under `bun run`.
8. **Platform promotion:** Who will capture the missing Windows and Linux installed-binary transcripts, particularly cancellation/process-tree cleanup, path/resource conversion, replay, and permissions?

## Resolution

OpenCode `v1.18.31` has a coherent, deep ACP capability envelope suitable for comparison against Secant's Harness threshold: structured stdio, early durable Session identity, genuine no-replay resume plus replaying load, final prompt responses, model/mode controls, permissions, cancellation, typed errors, and deterministic upstream fixtures. The truthful shape is narrower than Secant in the important places: no native Steer, no structured clarifications, cancellation confirmed only by the prompt result, close is detach rather than delete, and process cleanup remains client-owned. The pinned SDK's permissive/payload-logging transport must not be Secant's transport boundary.

This report does **not** choose whether OpenCode should occupy the third v1 Harness slot. It establishes capability and constraints. macOS arm64 has one direct release-binary happy-path qualification; Windows and Linux ACP runtime parity remain open gates.
