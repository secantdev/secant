# OpenCode ACP Three-OS Qualification

**Status:** Research conclusion for [Qualify OpenCode's released ACP binary across Secant's three v1 platforms](https://github.com/secantdev/secant/issues/178)

**As of:** 2026-09-21

**OpenCode qualified:** official stable [`v1.18.31`](https://github.com/anomalyco/opencode/releases/tag/v1.18.31), source commit [`014614d35b397775e5d397a490fc72368c894ec2`](https://github.com/anomalyco/opencode/tree/014614d35b397775e5d397a490fc72368c894ec2)

**Probe:** throwaway commit [`aeea2ffedffd8e8ae4375c0e9da3361155673cda`](https://github.com/secantdev/secant/tree/aeea2ffedffd8e8ae4375c0e9da3361155673cda), [probe source](https://github.com/secantdev/secant/blob/aeea2ffedffd8e8ae4375c0e9da3361155673cda/.research/opencode-three-os-qualification/probe.mjs), and [three-OS workflow](https://github.com/secantdev/secant/blob/aeea2ffedffd8e8ae4375c0e9da3361155673cda/.github/workflows/opencode-three-os-qualification.yml)

## Answer

OpenCode `v1.18.31` does **not** pass Secant's all-platform, all-ten-group qualification threshold. The result is **defer OpenCode from v1**; it does not earn the conditional third Harness slot. Claude Code and Codex remain the v1 Harness set, and this result does not delay the release.

Three direct release-binary failures independently settle the decision on Windows x64, macOS arm64, and Linux x64:

1. **Protocol compatibility:** initialization accepted requested ACP major `999` and returned major `1` instead of refusing the incompatible client. This matches the pinned implementation, which returns protocol version 1 without validating the requested major ([OpenCode initialize source](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L94-L139)).
2. **Recovery directory authority:** after restart, `session/resume` accepted an exact stored Session ID with a different `cwd`. Exact resume, no-replay behavior, load replay ordering, and missing-ID rejection cleared before this assertion; the directory mismatch alone failed. The pinned resume path restores the stored Session while constructing its ACP attachment from the request's directory snapshot ([OpenCode resume source](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/acp/service.ts#L295-L334)).
3. **Malformed-transport confidentiality:** malformed or truncated input containing a canary was reproduced in stderr. The pinned ACP SDK logs an entire malformed input line before dropping it ([SDK stream source](https://github.com/agentclientprotocol/typescript-sdk/blob/74372b59f8f56eb30e72f2538df2671a0adb376f/src/stream.ts#L51-L74)). This violates the gate's no-payload-leak requirement.

The same classification appeared in the [complete run](https://github.com/secantdev/secant/actions/runs/35560607483) on all three native runner shapes. A failure or unknown in any group on any platform is a whole-v1 deferral, so no partial-platform OpenCode claim follows.

GitHub's official [release metadata](https://api.github.com/repos/anomalyco/opencode/releases/tags/v1.18.31) is the digest authority.

## Evidence Boundaries

- Groups 2, 7, and 10 are direct, repeated release-binary observations on every target platform and are sufficient for the v1 deferral.
- Groups 6 and 8 remain useful probe findings but require corrected fixture/sequencing before they can support claims about OpenCode. They do not affect the already-settled decision.
- Group 9 remains unknown. Neither this run nor the earlier capability report establishes bounded forced process-tree cleanup on any target platform.
- The Windows `EPERM` occurred in the probe's final recursive temporary-directory removal. Because result serialization followed that cleanup in the throwaway script, no Windows JSON file was produced; the group lines in the job log remain the evidence actually available.
- This qualification makes no production support claim, changes no Harness Interface, and supplies no durable Adapter test. The probe and workflow remain throwaway research assets as required by the conditional-slot decision.

## Resolution

The all-three-platform rule is not met. OpenCode `v1.18.31` is deferred from Secant v1, with no partial-platform fallback. A later reconsideration needs a newly pinned release and must rerun the complete gate after correcting the cancellation fixture, configuration-option sequence, process-tree owner, and Windows result-write cleanup. Passing those probe repairs would not erase the observed protocol-major, directory-authority, or stderr-payload failures; the new release would also need to change or explicitly resolve each of those behaviors.
